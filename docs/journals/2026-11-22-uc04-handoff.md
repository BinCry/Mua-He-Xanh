# UC-04 handoff preview and delivery

## Context

The web already offered AI and staff chat, but switching modes did not deliver AI context to staff. The agreed flow is to show a read-only summary, allow an optional customer note, and deliver only after explicit confirmation.

## Changes and decisions

- Both chat surfaces preserve real handoff receipts and open the shared preview panel.
- Preview and send use server-to-server access to the agent packet. The browser cannot supply verified facts or a conversation owner.
- Confirmed summaries are stored as ordinary live-chat messages so existing admin/manager chat can display them without a separate dashboard.
- A deterministic message ID prevents duplicate delivery on retry. Customer notes remain separate from the system summary.
- Preview renders untrusted text through `textContent`; late preview responses do not switch modes after the panel has closed.

## Verification

`node --test test/agent-handoff.test.js test/handoff-preview.test.js test/template-compile.test.js test/agent-chat.test.js`: 25 passed. Coverage includes confirmation before send, safe rendering, duplicate preview clicks, closed-panel races, recoverable failures, trusted identity, canonical summary, wrong session owner, expiry, message deduplication and EJS compilation.

No live browser or database-backed end-to-end test was performed in this review.

## Remaining work

This delivers the preview/send integration slice. Staff presence, a persistent handoff lifecycle dashboard, resolve/resume controls and complete retention are separate follow-up work; full UC-04 acceptance is not claimed.
